# Image assets

**Summary:** the sites currently contain **no photographs**. The previous website
(`https://glazebrookecoffee.com`, including `/beyond-coffee/`) could not be
reached during the build, and the owner did not have a copy of its images, so
no original estate photography could be reused. No stock or AI-generated
photographs have been used in their place.

Every photo position is a named **slot**. Until a real photograph is supplied, the
slot shows a contour-line drawing of hills, generated in code at build time,
with a visible caption "Photograph to come: …". These drawings are decorative
(`aria-hidden`) and do not depict the estate. Product cards hide the caption.

To recover the old site's images, run `npm run import:legacy` from a machine that
can reach the old site (see README), then confirm reuse rights for each image
before adding it here.

## 3. Image handling

- Formats: AVIF and WebP with a JPEG fallback via `<picture>`, at widths up to
  2000px (2560px for the home hero), capped at the original's width.
- Loading: hero and product images use `loading="eager"` with
  `fetchpriority="high"`; all others are `loading="lazy"`.
- Every image has explicit width and height, and slots use CSS `aspect-ratio`, so
  layout does not shift while images load.
- Filenames are descriptive slot names (for example `estate-shevaroy-view`), which
  carry into the hashed output names.

## 4. Rules for adding images

1. Use only genuine photographs of Glazebrooke in estate, people and product slots.
   The alt text and page context present them as the estate.
2. Confirm the right to publish. Being visible on the old website is **not**
   proof of reuse rights: check who took each photo and whether a photographer
   or agency licence applies.
3. Get consent from identifiable people, especially estate workers.
4. If a non-documentary image is ever needed (for example a brewing illustration),
   label it as such and record its licence in this file.
